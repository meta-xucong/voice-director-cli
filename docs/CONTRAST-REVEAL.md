# Contrast-reveal visual sequence

## Frozen implementation contract

**User goal:** automatically recognize when a lesson needs a visual comparison, plan a clear real-asset sequence, and use motion to direct attention from context to detail to a useful takeaway. The current Codex-versus-ChatGPT Work sample is the acceptance example.

**Baseline:** `editorial-gate-20261023` at `91ea6dff456d2fb1d192e3fce93a1bbbf8818e88`, clean before this change. The existing sample uses genuine user-supplied desktop captures, but only swaps full screenshots and adds labels; the map has no cross-beat sequence contract.

**Design intent:** show the full first screenshot long enough to establish context, animate exact evidence crops from their source positions into a centered detail, and then restore the same sequence for the second screenshot. Finish with both sharp evidence crops side by side in a stable center composition, labeled with the two spoken concepts and the learner-facing takeaway. Preserve orientation with source-linked motion and matched pacing. While a detail crop overlaps its still-visible full screenshot, softly defocus the screenshot (`context_background: "blurred_source"`; the approved sample uses `context_blur_px: 8`). If the full image is removed or replaced, record that instead and set blur to zero. Use smooth ease-in/ease-out movement, settle before text holds, keep the evidence crop sharp, and time holds to the actual spoken sentence so the edit does not insert dead air. All source crop bounds and straight annotation edges must land on the integer pixel grid; never rotate, skew, or use perspective on callout frames. Keep authentic screenshot pixels as evidence and use crisp vector labels for legible teaching text. Never fabricate product UI or claim that structural validation proves semantic truth or visual polish.

**Automatic behavior boundary:** the harness infers a comparison/reveal pattern from narration and learning intent, cites the trigger, chooses authentic reviewed assets, defines the stages and source-pixel crops, and explains the takeaway. The offline CLI validates declared stage order, timing, crop bounds, matching authentic sources, and explicit human-review uncertainty. It does not run an LLM or decide whether a passage semantically needs comparison. If no adequate genuine source image exists, or the crop cannot support a readable detail at the output scale, the harness must show the concrete gap and ask the user whether to supply an image or approve a clearly labeled original diagram.

**Hard constraints:** use the existing HyperFrames/GSAP renderer; do not add a second renderer, new provider, network client, or dependency. Keep courseware screenshots, rendered sample, audio, and frame evidence in the private run directory. Preserve prior sample hash approval semantics: any new render requires fresh user approval before a full lesson render.

**Allowed files:** `docs/CONTRAST-REVEAL.md`, `docs/PIPELINE.md`, `docs/VISUAL-QUALITY-GATE.md`, `README.md`, `skills/courseware-pipeline/SKILL.md`, `voice_director/voice_screen.py`, `voice_director/cli.py`, and focused tests for the sequence validator/CLI. ## Map contract

Add `visual_sequences` only when a cross-beat visual sequence materially improves learning. A `contrast_reveal` has five ordered beat references: `context_a`, `detail_a`, `context_b`, `detail_b`, and `synthesis`. Each referenced beat repeats `{ "id": "...", "stage": "..." }` in `visual_sequence`; context/detail beats also identify slot `a` or `b` as `participant_id`.

The sequence names a narration-grounded `trigger` and a learner-facing `takeaway`. Its two participants declare a concise label, their role in the lesson, and a genuine source capture. `source_pixel_regions` contains one or more named evidence crops, each with exact source pixels and its planned output display size. Use separate crops when identity and relevant workflow evidence occur in different parts of a screenshot. The same authentic `real_ui` source must occur in the participant's context and detail beats and in the synthesis beat. The validator requires finite numeric geometry within a one-million-pixel per-dimension safety bound, checks every crop remains within source bounds and cannot be upscaled at the declared maximum display size, and verifies declared holds fit within their corresponding beat durations. The harness still decides whether the crops actually prove the spoken claim and are legible.

`motion` declares one primary movement (`source_linked_zoom`, `mask_reveal`, `matched_push`, or `slide_align`), the required `ease_in_out` easing and `integer_pixel_grid` alignment, a required background treatment (`blurred_source` or `removed_or_replaced`), an explicit `context_blur_px` value from 0–16 output pixels, and context, reframe, detail, and synthesis timing. The declared full-context hold is the clear, unobscured time after the screenshot fade-in has settled; it must be at least 2.5 seconds before the selection cue or crop motion begins. Blurred source requires blur above zero; removed/replaced source requires zero. Every crop origin, crop size, source size, and planned display size must use integer pixels. The renderer must apply easing to the crop travel and blur, settle the crop before the legibility hold, and restore/remove the background as the crop leaves. Anchor scene boundaries to narration/audio; do not add silence just to lengthen a static frame. Allowed ranges favor enough time to recognize and read evidence while keeping transitions fluid. Vary local masks, callouts, and emphasis within a scene when they help; do not layer competing movement or drift across a reading hold. If the evidence, label, or crop fit is uncertain, attach the usual `question`, `evidence`, `impact`, and `recommendation` packet to the sequence. A pending packet produces `AWAITING_HUMAN`.

The harness should look for comparison intent in the teaching goal and narration, including contrast, equivalence, correspondence, alternatives, and before/after relations; keyword matching alone is not sufficient. It chooses this pattern only when viewers benefit from seeing evidence in the source context before focusing and comparing. Otherwise keep the normal beat map. If a genuine screenshot or high-resolution crop is missing, search/review assets first; then show the precise visual gap and ask the user whether to supply a capture or approve a clearly labeled original diagram. Never synthesize or imply genuine product UI.

Run the regular `validate-voice-screen` command after adding sequences. It returns the declared sequence stages and any pending human decisions alongside the beat report. Passing only confirms structural checks; the harness must inspect the actual sample at 1× and the user must approve its exact hash before full rendering.
